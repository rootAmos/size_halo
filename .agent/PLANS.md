# Execution plans

Write a self-contained plan before adding a tier, changing an interface, spanning
disciplines, or changing topology or optimization. Implement only the active plan.
Record goal, scope, tier, references, assumptions, inputs, outputs, parameters,
design variables, states, controls, equality and inequality constraints,
interfaces, symbolic considerations, tests, reference cases, implementation
sequence, acceptance criteria, progress, decisions, and deferred work.
Keep plans in `plans/active`; move accepted plans to `plans/completed`.
